# Implemented instruction audit

This audit covers the **115 original dispatched mnemonics**, including the existing `RTD`, `MOVE from CCR`, and custom `MODE` extensions. It evaluates instruction results, operand forms and sizes, condition codes, address side effects, and modeled exceptions. It does not claim binary or cycle-accurate CPU emulation.

## Reference and decisions

The requested [instruction reference](https://github.com/prb28/m68k-instructions-documentation/tree/89744462bde926313aa273dde2109b680ed11c8a) is pinned to commit `89744462bde926313aa273dde2109b680ed11c8a`. Each instruction row links to that revision. Ambiguities and processor-version differences are resolved with the [Motorola M68000 Family Programmer’s Reference Manual](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf).

- The target is the original 68000, with the existing extensions listed above. In particular, `MULS`/`MULU` and `DIVS`/`DIVU` use word operands, `CHK` is word-sized, and PC-relative `TST`/`CMPI` are rejected as later-processor forms. Reserved SR bit 14 is not a second trace bit.
- `STOP` checks the existing supervisor state before loading its immediate SR. A supervisor-mode `STOP #0` therefore loads user mode and stops. This follows the primary manual’s operation (section 6, STOP), rather than the supplied repository’s statement that clearing S in the immediate necessarily causes a privilege violation.
- PC-relative effective addresses use the address of the EA extension word: normally instruction address +2, or +4 after a static bit number or `MOVEM` register mask. Symbolic targets use signed, wrapping 32-bit differences. Numeric displacements also accept signed-field bit patterns; symbolic distances must actually fit the signed field.
- `MOVEM` uses 68000 behavior when a predecrement base is included in the register list: store its original value. Word loads sign-extend into both register classes. Postincrement finally overrides a loaded base register.
- `MOVE.W/L` to An remains an assembler alias for `MOVEA`, and branch aliases `BHS/BLO`, `DBRA/DBHS/DBLO`, and `SHS/SLO` resolve to the corresponding existing mnemonic. They do not add CPU operations.

## Compatibility and retained model limits

- Real instructions occupy **four virtual bytes**, irrespective of hardware encoding. Labels consume no bytes; data directives advance the address by their actual size. With no `ORG`, virtual addressing starts at zero. Instructions are interpreted from source, not encoded into memory; self-modifying machine code is unsupported.
- Calls stack the next **virtual** instruction address. Every return converts its stacked virtual address back to a source instruction. Unmapped targets halt. Falling through a later `ORG` boundary halts; returning into its preceding gap preserves this behavior. Gaps remain sparse.
- Branch operands denote target addresses, not literal encoded displacements. Explicit branch sizes enforce displacement limits; unsuffixed branches retain unrestricted virtual target resolution. There is no instruction-length relaxation or cycle timing.
- Memory is sparse, big-endian, byte-addressable, and wraps at 32 bits. It does not implement the 68000’s 24-bit physical bus, alignment/bus exceptions, peripheral side effects, or extra bus cycles. Unaligned memory accesses remain supported.
- There is one modeled A7, with the correct two-byte byte-access stride. Separate user/supervisor stacks, exception vectors, hardware interrupts, trace execution, and interrupt wake-up from `STOP` are not implemented. `MOVE USP` is outside the existing instruction set.
- Traps, division by zero, failed `CHK`, and privilege violations save a six-byte SR/virtual-PC frame on the modeled stack and halt. `RTE` handles that modeled frame, not other processors’ frame formats. `RESET` checks privilege but has no external devices to reset. `TAS` is indivisible within this single-threaded interpreter, without bus arbitration.
- Invalid instruction forms stop with a line-specific diagnostic before operand side effects. General immediates accept the selected width’s signed values or unsigned bit patterns; quick counts, shift counts, `MOVEQ`, and trap vectors have their own ranges. `MOVEQ` requires −128…127; write `#-1` instead of `#$FF`.
- Unsuffixed general arithmetic, logical, and register shift operations default to **word**, replacing the old logical/shift long default. Use explicit `.L` where needed. Fixed-width instructions retain their documented width. CCR logical operations are byte-sized; status moves and SR logical operations are word-sized.
- Undefined flags are not asserted as hardware guarantees. Division overflow preserves previous N/Z deterministically while setting V and clearing C; the original destination and X remain intact.
- Expressions support numeric bases, single character literals, symbols/current address, unary signs, and left-associative addition/subtraction. This is not a complete assembler expression or macro language.

## Coverage key

All rows have validation coverage in [instruction-validation.test.ts](../tests/instruction-validation.test.ts), including invalid operand count/size for every original mnemonic. The execution coverage below uses:

- **I** — [instruction-conformance.test.ts](../tests/instruction-conformance.test.ts): register and memory results, widths, addressing, transfers, flags, every conditional mnemonic across all 32 CCR combinations, and parser/address boundary regressions.
- **C** — [control-system-conformance.test.ts](../tests/control-system-conformance.test.ts): calls, returns, exact stack frames, status/privilege operations, extensions, undo/reset, and bounded termination.
- **A** — [alu-conformance.test.ts](../tests/alu-conformance.test.ts) and [arithmetic-flags.test.ts](../tests/arithmetic-flags.test.ts): independent arithmetic and BigInt shift oracles, boundary counts, overflow, cumulative zero, and preserved bits.

“Corrected” includes shared operand/validation fixes; it does not imply every part of the prior ALU implementation was wrong. “Verified” identifies execution semantics retained and covered by tests. Coverage checks representative forms and boundaries, not every possible machine state.

## Validation and example migration

The original suite remains in place. Tests that intended long logical/shift operations now say `.L`; call-address assertions now expect the continuation address; status tests distinguish supervisor execution from privilege faults. Regression programs assert termination, not merely a register value after a fixed number of loop iterations.

The bundled factorial, Fibonacci, loop-counter, stack, and bubble-sort programs continue to use legal forms. Their intentional terminal loops are checked with bounded execution. The original `RTS` and manual `MOVEA.L (SP)+,A0` / `JMP (A0)` examples both terminate for BSR and JSR and restore SP.

Required final checks: `npm test -- --run`, `npm run lint`, `npm run build`, and `git diff --check`. The build includes TypeScript checking. Public `Emulator` methods retain their signatures; internal operand and undo-state types now carry the data needed for consistent execution and restoration.
